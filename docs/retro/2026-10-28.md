# Retro — 2026-10-28

A retrospective on the build of Nana Pearl's Arrow Slide Puzzle, and the
environment changes made from it.

## What went well

- The pure engine, solver, reverse-construction generator, and solver-verified
  content gave the review agents something trustworthy to stand on. No clearance,
  solver, level-data, or save-migration defect survived either review round.
- The deep-violet visual system and progressive frost reveal held up across
  every viewport; the constellation gallery and Nana Pearl were consistently
  called out as genuine differentiators.
- A single integration branch, a spec issue, eight tracer tickets, and a PR that
  closed them all kept the work legible.

## What cost us

1. **“Responsive” was claimed from two viewports.** The first pass checked
   390×844 and 320×568. Review found 375×667 footer overflow, short-landscape
   dialog clipping, a 12 px board at 400% zoom, and a 390 guide shift. The fix
   was a viewport matrix and a stable reserved guide slot.
2. **Claims outran measurements.** The README said 44 px targets everywhere;
   the real range was 26–50 px. The README, accessibility doc, and ticket were
   corrected, and the measurements now live in one table.
3. **A visible control was not click-tested.** The dialog X looked fine in
   screenshots but was painted over by the eyebrow. Browser tests now click
   every close control; the settings focus trap is exercised too.
4. **Offline was proven warmly.** Reloading the controlled tab could pass on
   HTTP/module caches. The suite now opens a cold tab offline, and the service
   worker matches with `ignoreVary`.
5. **The reveal was spoiled in previews.** Level-select cards showed the full
   constellation line work. Muted art now hides lines, stars, and orbits until
   completion.

## Environment changes made

- `npm run verify` combines typecheck, unit/solver tests, build, and Playwright.
- `CODING_STANDARDS.md` has a Release Surface section: measured claims, clicked
  close controls, the full viewport matrix, cold-tab offline evidence, and
  regenerated content.
- The browser suite adds an 8×8 target-size floor at 320/390 and a win-dialog
  close click.
- `docs/evidence/README.md` documents how to regenerate every capture and the
  Lighthouse run.

## Next opportunities

- Add a forced-colors/grayscale smoke pass for the settings tick and board
  states.
- A visual screenshot diff for the board at the supported viewports would catch
  silhouette regressions that DOM assertions miss.
- If daily/endless levels are ever added, fold the generator into a runtime
  budget test before shipping.
